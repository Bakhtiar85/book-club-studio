# Book Club Studio: instructions for Claude Code

This folder makes **"Book Club with Noor & Baba"**, a YouTube Shorts series where a daughter (Noor, the dreamer) and her father (Baba, the skeptic) read a book chunk by chunk in a cozy library. A narrator takes us *into* the book. You are the writer, director and programmer. The user mostly types one command.

## Start of EVERY session (don't skip; this is how each episode knows the past)
Read, in this order:
1. `series/bible.md`: the show's fixed identity, rules, release calendar and book cycle
   `series/design.md`: look and feel, the venue, book themes, new-character rules (read it before drawing anything)
2. `series/continuity.md`: running jokes, open promises, vote scoreboard
3. `series/EPISODES.md`: what's been made and published (regenerate first with `python tools/status.py`)
4. the active book plan in `series/books/`
5. `notes.md` of the **last two episodes** in `episodes/`
6. **the bookmark:** `python tools/book.py where <book>` shows exactly where the story stopped (page, event) and what comes next

## Commands the user will type
| Command | What it does |
|---|---|
| `/setup` | first-time install + checks (run once per computer) |
| `/upgrade-characters [hosts\|<book>]` | redraw characters with more polish, keeping the same look and code API (needs the user's approval) |
| `/book-status` | where we are, what's next, days since last upload |
| `/next-episode` | writes, voices, animates, renders and logs the next part, with **one** approval stop (the script) |
| `/render <ep>` | re-render an episode after edits |
| `/upload-pack <ep>` | everything to fill YouTube Studio's upload form, in form order (alias: `/ep-upload-pre-req`) |
| `/published <ep> <url>` | marks it uploaded today |
| `/results <ep> views=.. noor=.. baba=..` | logs results and the vote, updates the scoreboard |
| `/finale` | the book's last Short: recap, final verdict, season scoreboard, viewers vote on the next book |
| `/compile-book <book>` | end of month: all parts stitched into one long YouTube video with chapters |
| `/new-book <title>` | plans a new book as numbered parts (from its PDF if there is one), designs its world and new characters, and shows the character sheet for approval |
| `/add-pdf <book> <path>` | adds a book's PDF, extracts the text, aligns the bookmark and plan with page numbers |

YouTube packaging/analysis skills (from `.claude/skills/yt-*`, wired into the commands above — see below): `/yt-script`, `/yt-package`, `/yt-seo`, `/yt-retention`, `/yt-chapters`, plus `/yt-audit`, `/yt-comment`, `/yt-edit`, `/yt-plan`, `/yt-shorts`, `/yt-viral` available standalone. Voice profile lives at `~/.claude/youtube/voice.md`.

## script.json format
```jsonc
{
  "book": "The Alchemist", "author": "Paulo Coelho",
  "part": "Part 2: Tangier",                 // shown in the top chip
  "question": "Trust strangers?",            // vote card title
  "vote": {"noor": "be brave", "baba": "be careful"},
  "next": "Next: Part 3 · The Crystal Merchant",
  "source": {"book": "the-alchemist", "pages": "33-48", "ends_at": "robbed in the market"},  // bookmark info
  "book_open": {"line": 1, "word": "Look"},  // the word where Noor's book flies up
  "speakers": { "baba": {...}, "noor": {...}, "narrator": {...} },   // copy from the previous episode
  "lines": [
    {"who": "baba", "text": "…", "gap": 0.25,
     "fx": [{"on": "word", "punch": true, "shake": true, "react": "?!|!|stars|sweat|heart", "react_dur": 1.5, "happy": 1.2, "sound": "dundun"}]},
    {"who": "noor", "text": "… Look!", "gap": 0.7},
    {"who": "narrator", "scene": "market", "ambience": "town", "text": "…",
     "sfx": [{"on": "coins", "sound": "coins"}]}
  ]
}
```
- `on` = a word that appears in that line (punctuation ignored). `tools/voice.py` fails loudly if a cue word is missing.
- Every narrator `scene` id must exist in that episode's `SCENES`. Narrator lines must be **one contiguous block**, preceded by ≥ 2 room lines and followed by ≥ 2.
- `happy` (seconds) makes Noor smile with closed eyes. Reactions float over the speaker (override with `"who"`).

## Books, PDFs and the bookmark (where we left off)
- `library/<book>/bookmark.json` is the **reading position**: `covered_to_page`, `next_start_page`, `last_event`, `next_hint`, plus a `history` of which episode covered which pages and events. It is the single source of truth for "where did we stop?". Never guess it from memory.
- **Before writing a script:** run `python tools/book.py where <book>`. If there's a PDF, read the next chunk with `python tools/book.py pages <book> <start>-<start+15>` (more if needed) and pick a natural stopping point: a scene end, a cliffhanger, a chapter break. Use `book.py find` to check names and details.
- Put the chunk's pages and end event in `script.json` → `"source": {"book": "<book>", "pages": "33-48", "ends_at": "…"}`.
- **After the final render:** `python tools/book.py advance <book> --episode <ep> --pages 33-48 --event "<what happened, 1 line>" --next "<what comes next, 1 line>"`, and write the pages into the episode's `notes.md` and the book plan.
- **Originality:** the PDF is a fact source only. Write every line in our own words. `tools/voice.py` runs `tools/originality.py` automatically and refuses to voice any line that shares 8+ consecutive words with the book. At most ONE short quote per episode (≤ 15 words), marked on its line as `"quote": "exact words"`, and only if it really adds something.
- The PDF and extracted text never leave this computer: don't paste them into descriptions, comments or on-screen text.
- No PDF? Work from the plan and verify facts with web search, and keep the bookmark updated anyway (pages stay null).

## Engine rules (don't break these)
- All motion comes from Remotion time (`useCurrentFrame`). No CSS animations, timers or randomness without a fixed seed (`rnd(i)`).
- Story scene components receive `{ t, lt, s0 }`: global time, scene-local time, and scene start. Cue a reveal with `at("word", lineIndex) - s0`.
- Characters are 2D SVG components in the house style (`series/design.md`). **Reuse** book characters from `world.tsx`. Add new ones there (and to `CharacterSheet`), never inside one episode. New recurring characters need the user's approval on the sheet.
- Keep y 1500–1650 (captions) and the top chip clear of important action.
- Don't edit `src/current/`. Don't edit `engine/Main.tsx` for a single episode; if the engine needs a feature, add it generally and keep old episodes rendering.

## Quality check (before showing ANY render)
Run `python tools/render.py <ep> --draft`, then open `episodes/<ep>/out/contact.jpg` and look at **every** tile:
- first line ≤ 0.3 s, story visible by ~5 s, total ≤ 60 s
- each scene matches its narration line; reveals land on their words
- no broken or overlapping limbs, nothing under the captions, no empty or black frames
- captions spelled right, in the right speaker colour
- Noor and Baba mouths move only on their own lines
Fix and re-check, then do the final render (no `--draft`). Tell the user what you caught and fixed.

## After every episode (memory for next time)
1. `episodes/<ep>/notes.md`: story covered, debate sides, jokes used, **promise for next episode**
2. `episodes/<ep>/publish.md`: title (≤ 60 chars, curiosity hook), 2-line description, 5–6 hashtags, pinned vote comment, and its **Upload checklist** (Audience / Age restriction / Altered content disclosure / Comments)
3. `series/continuity.md`: new jokes, promises (and mark old ones paid off), scoreboard row
4. `series/books/<book>.md`: mark the part 🎬 (with its pages), set the next one 📝
5. move the bookmark: `python tools/book.py advance …` (see above)
6. `episodes/<ep>/episode.json` status, then `python tools/status.py`
7. **In your final reply to the user**, always include the Upload checklist from `publish.md` so it isn't missed before uploading.
8. Commit the episode: `git add -A && git commit -m "Episode NNN: <part title>"` (e.g. "Episode 002: Tangier").

## YouTube packaging skills (`.claude/skills/yt-*`)
Installed from [youtube-agent-skill](https://github.com/Jakeschincariol/youtube-agent-skill), project-scoped. All read `~/.claude/youtube/voice.md` (the show's voice: Noor & Baba, warm, short lines, family-friendly) and none of them publish anything — they only write files for the user to upload.
- `/next-episode` scores Baba's hook line with `yt-script`'s `hookscore.py` before the approval stop, and offers a stronger alternative if it bands WEAK.
- `/next-episode` writes `publish.md` using `/yt-package` (title + thumbnail brief off `cover.jpg`) and `/yt-seo` (description, tags, pinned comment).
- `/results` runs `/yt-retention` on a provided retention CSV (`--retention <path>`) and logs its biggest-leak takeaway to `continuity.md`.
- `/compile-book` validates the chapter list with `/yt-chapters` before writing the compilation's `publish.md`.
- `/yt-audit`, `/yt-comment`, `/yt-edit`, `/yt-plan`, `/yt-shorts`, `/yt-viral` are available standalone, not wired into any command.

## Troubleshooting
- Voices: `tools/voice.py` needs `kokoro-onnx` and the two model files in `kokoro_dir` (`/setup` downloads them).
- Render fails to launch the browser: set `browser_executable` in `studio.config.json` to Chrome, or let Remotion download its own (default).
- Slow renders: set `render_concurrency` (e.g. 4) in `studio.config.json`.
